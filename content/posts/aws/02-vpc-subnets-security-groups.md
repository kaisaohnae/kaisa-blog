# VPC·서브넷·보안 그룹으로 네트워크 설계하기

> 요약: 퍼블릭/프라이빗 서브넷, 라우팅, 보안 그룹·NACL의 역할을 구분하고 실무에서 쓰는 최소 VPC 뼈대를 잡는다.

---

## 1. VPC가 하는 일

VPC는 계정 안의 **격리된 네트워크**다. CIDR, 서브넷, 라우트 테이블, 게이트웨이로 구성한다.

권장 시작:

- CIDR: `10.0.0.0/16` (팀 표준이 있으면 그에 따름)
- AZ 2개 이상
- 퍼블릭 서브넷 + 프라이빗 서브넷

---

## 2. 퍼블릭 vs 프라이빗

| 구분 | 특징 | 예 |
|------|------|-----|
| 퍼블릭 | IGW 경로, 공인 IP 가능 | ALB, NAT, 배스천 |
| 프라이빗 | 인터넷 직접 노출 없음 | EC2 앱, RDS |

앱 서버를 퍼블릭에 바로 두는 구성은 데모용으로만 두고, 실무는 **ALB(퍼블릭) → 앱(프라이빗)** 이 기본선이다.

---

## 3. 보안 그룹 vs NACL

- **보안 그룹(SG)**: 인스턴스/ENI 방화벽. stateful. 허용 규칙 위주.
- **NACL**: 서브넷 방화벽. stateless. 보조 계층.

실무에서는 **SG를 주 통제**, NACL은 기본(allow)으로 두는 경우가 많다.

```
ALB SG  : 0.0.0.0/0 → 443
App SG  : ALB SG → 8080
DB SG   : App SG → 5432
```

CIDR을 넓게 열지 말고 **소스에 다른 SG ID**를 넣는 편이 안전하다.

---

## 4. NAT·엔드포인트

프라이빗에서 아웃바운드(패키지 설치·API 호출)가 필요하면:

- NAT Gateway (간단, 비용↑)
- VPC Endpoint (S3/DynamoDB 등 비용·보안 유리)

---

## 정리

네트워크는 “일단 다 연다”가 아니라 **계층(퍼블릭/프라이빗) + SG 최소 허용**으로 시작한다.
